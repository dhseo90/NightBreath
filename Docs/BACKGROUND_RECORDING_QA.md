# 백그라운드 녹음 QA

NightBreath / 밤숨 V1은 iPhone 내부에서 수면 중 소리 이벤트 요약을 만드는 웰니스 앱입니다. 이 문서는 화면 잠금 또는 백그라운드 상태에서 앱 세션 시간과 실제 오디오 수신 시간이 서로 다른지 확인하기 위한 개발자용 QA 기준입니다.

## 구분해야 하는 시간

- 앱 세션 경과 시간: 사용자가 수면 시작을 누른 시각부터 수면 종료를 누른 시각까지의 wall-clock 시간입니다.
- 실제 오디오 수신 시간: `AudioChunk.frameCount / sampleRate`를 누적한 시간입니다. 단순한 Date 차이가 아니라 실제 마이크 chunk가 들어온 양을 기준으로 봅니다.
- 실제 분석 시간: `SleepAnalyzer`가 처리한 chunk의 frame 기반 누적 시간입니다.

## 화면에서 볼 값

- 세션 경과
- 오디오 수신
- 분석 시간
- 녹음 커버리지
- 마지막 오디오 입력
- 마지막 분석
- 마지막 이벤트 감지
- 앱 lifecycle 상태
- 마이크 권한 상태
- background audio mode 설정 여부
- 오디오 chunk 수
- 분석 chunk 수
- 오디오 중단 횟수
- 가장 긴 입력 공백
- 현재 입력 공백
- 원본 전체 오디오 저장: 꺼짐
- 저장된 이벤트 오디오 시간

## 저장 안전장치

- 일반 수면 기록에서는 원본 전체 밤 오디오를 저장하지 않습니다.
- 이벤트 판단 시점 확인을 위한 짧은 이벤트 오디오 샘플만 로컬에 저장할 수 있습니다.
- 이벤트 오디오 샘플 기본 정책: 이벤트 전 2초, 이벤트 후 3초, 샘플 최대 10초, 세션당 최대 100개, 폴더 최대 200MB, 7일 보관.
- 이벤트 오디오 샘플 저장 위치: `Application Support/NightBreath/EventAudioSnippets/`
- 이벤트 오디오 샘플은 앱에서 재생하고 개별/전체 삭제할 수 있어야 합니다.
- 제품화 전에는 이벤트 오디오 샘플 저장을 사용자 opt-in 설정으로 분리해야 합니다.
- DEBUG 샘플 수집은 사용자가 직접 누른 짧은 샘플만 저장합니다.
- 샘플 1개 최대 길이: 5초
- 앱 실행당 최대 샘플 수: 100개
- 샘플 폴더 최대 용량: 200MB
- 7일이 지난 DEBUG 샘플은 저장 전 정리합니다.
- 저장 전 여유 디스크 공간을 확인합니다.
- 저장 실패 시 앱이 종료되지 않고 오류 메시지를 표시해야 합니다.

## 성공 기준

- 화면 잠금 3분 테스트에서 오디오 커버리지 95% 이상
- 앱 백그라운드 3분 테스트에서 오디오 커버리지 95% 이상
- 잠금 30분 테스트에서 오디오 커버리지 95% 이상 권장
- 마지막 오디오 입력 시각이 현재 시각과 크게 벌어지지 않아야 함
- 가장 긴 입력 공백이 테스트 의도와 맞지 않게 길게 증가하지 않아야 함

## 실패 예시

- 세션 경과 시간은 3분인데 실제 오디오 수신 시간이 30초인 경우
- 실제 분석 시간이 실제 오디오 수신 시간보다 크게 낮은 경우
- 마지막 오디오 입력 시각이 2분 이상 전인 경우
- `longestAudioGapSeconds` 또는 가장 긴 입력 공백이 지나치게 큰 경우
- 화면 잠금 직후 chunk 수가 더 이상 증가하지 않는 경우
- 실제 오디오 수신과 분석은 장시간 유지되지만 이벤트가 0개인 경우. 이 경우 detector threshold 또는 smoothing이 지나치게 보수적인지 추가 진단 로그가 필요합니다.

## Test A: foreground 1분

1. 앱 실행
2. 수면 시작
3. 1분 대기
4. 세션 경과, 오디오 수신, 분석 시간이 함께 증가하는지 확인
5. 수면 종료
6. 리포트 생성 확인

## Test B: 화면 잠금 3분

1. 수면 시작
2. 화면 잠금
3. 3분 대기
4. 앱 다시 열기
5. 마지막 AudioChunk 수신 시각 확인
6. 수면 종료
7. 측정 시간이 3분 이상인지 확인
8. 녹음 커버리지가 95% 이상인지 확인

## Test C: 앱 백그라운드 3분

1. 수면 시작
2. 홈 화면으로 나감
3. 3분 대기
4. 앱 복귀
5. 마지막 AudioChunk 수신 시각과 lifecycle 로그 확인
6. 수면 종료
7. 리포트 생성 확인
8. 녹음 커버리지가 95% 이상인지 확인

## Test D: 잠금 30분

1. 충전 연결
2. 수면 시작
3. 화면 잠금
4. 30분 대기
5. 앱 복귀
6. 수면 종료
7. 측정 시간, 실제 오디오 수신 시간, 리포트, 배터리, 발열 확인
8. 가장 긴 입력 공백이 지나치게 크지 않은지 확인

## Test E: overnight

1. Test A~D 통과 후 진행
2. 충전 연결
3. 저전력 모드 끄기
4. 마이크가 막히지 않게 iPhone 배치
5. 수면 시작
6. 아침에 수면 종료
7. 리포트, 이벤트 수, 저장 용량, 배터리, 발열 확인
8. 녹음 커버리지와 마지막 오디오 입력 시각 확인
9. 이벤트가 0개이면 raw 후보 수, smoothing 전/후 후보 수, RMS/energy 요약을 별도 진단 로그로 남겼는지 확인

## 해석 가이드

- 녹음 커버리지 95% 이상: 백그라운드 또는 잠금 상태에서도 실제 오디오 수신이 대체로 유지된 상태입니다.
- 녹음 커버리지 85~95%: 일부 공백이 있었을 수 있으나 짧은 QA에서는 계속 관찰이 필요합니다.
- 녹음 커버리지 60~85%: 측정 품질이 제한적입니다. 기기 잠금, 앱 상태, 권한, 오디오 세션 interruption을 확인합니다.
- 녹음 커버리지 60% 미만: 리포트 신뢰도가 낮을 수 있습니다.

## 현재 진단 로그 한계

현재 리포트에는 앱 세션 시간, 실제 오디오 수신 시간, 실제 분석 시간, 녹음 커버리지, 오디오 중단 횟수, 가장 긴 입력 공백이 저장됩니다.

아직 세션별로 영구 저장하지 않는 값:

- raw detector 후보 수
- smoothing 전/후 후보 수
- threshold별 통과/탈락 수
- RMS/energy 분포 요약
- detector가 이벤트를 만들지 않은 이유

따라서 장시간 측정에서 이벤트가 0개이면 “실제로 조용했는지”와 “detector가 너무 보수적이었는지”를 사후에 완전히 구분하기 어렵습니다.

이 앱은 진단 목적의 의료기기가 아니며, 리포트는 수면 중 소리 기반 참고 지표입니다.
